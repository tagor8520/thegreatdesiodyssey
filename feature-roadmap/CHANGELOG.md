# Feature Changelog

All significant feature, architecture, research, budget, and roadmap changes are recorded here. Entries use local project dates (`Asia/Kolkata`) and canonical IDs from [`README.md`](./README.md).

This project does not yet publish semantic releases. Until it does, changes are grouped by date and implementation state. A source change is listed as **Added** only after its test/build gate passes; unfinished work stays under **In progress**.

## Unreleased

### In progress

- `MAT-03` — The low-pixel-ratio shimmer capture that was the recorded blocker has now been **run**, at the production adaptive pixel-ratio floor of `0.6`, and it is **inconclusive**. Measured against a mip-disabled control and against a positive control with the *entire* anti-alias policy stripped, the 99.9th-percentile frame-to-frame luma delta stays pinned at `4.1` in every configuration (`1.000x` sensitivity): the statistic cannot detect aliasing even when the policy is removed, so it certifies nothing. The task stays `PARTIAL`; the open gate is now a real-GPU capture. **An earlier `0.890x` figure reported here has been withdrawn** — see Changed.

### Added

- `NET-01` — Added `src/engine/SaveState.js`, the versioned local save both runtimes now write, and `src/engine/SaveState.test.js` (13 tests). One document under one key (`gdo:save`) carries three sections — `settings`, `discovery`, `progress` — stamped with `schemaVersion` (`saveSchema` moved `0 → 1`) and the generator registry version. The shape is declared rather than implied: `SAVE_SETTING_FIELDS` is a table with a fallback per field, so an undeclared key, a missing key and a wrong-typed key are each a *problem*; the caps are one byte limit (64 KiB) and the count limits (`128` discoveries, `64` states, `64` collected per state, the last taken from `STATE_CONTENT_LIMITS` so the journal and the document cannot disagree); `validateSave` separates problems from advisory warnings (a document from another generator build loads with a warning, a document from a **newer schema** or with garbage in it does not load at all); `SAVE_MIGRATIONS` is a pure ladder whose `0 → 1` step re-derives every discovery id from its own name/kind/anchor, coerces the pre-schema `0`/`1` booleans against the declared table, drops undeclared settings with a note, and dedupes collected ids; and `SaveStore` writes only when something changed and at most once per interval, trimming an over-ceiling document **oldest-first** rather than refusing it, which is the one failure a player cannot recover from. The load path is deliberately conservative: an unreadable document is never adopted and never overwritten in place — the runtime mounts empty and the text is copied to `gdo:save:unreadable` — and the writer refuses exactly what the reader refuses. **Both runtimes are wired**: `GeoGame` reads before it builds the world and restores the journal `GME-06` feeds, `main.jsx` removes the collectibles a previous session took (`items.restore`) and applies the saved sound preference before anything plays, and `landing.js` resumes the last coordinate in the shell, before any 3D loads. A restored reading is **rebased into the live clock's frame** rather than trusted as a time, because every page load restarts the clock the journal reads; `DiscoveryJournal.restore()` correspondingly no longer moves the journal's own clock, so restoring a save cannot make the next frame look like a backwards clock. Ids are the runtime's own (`vada-pav:0`), keyed by state pack (`maharashtra`), so the save speaks the vocabulary `ItemManager` and the content packs already use. **Gate: `npm run visual:audit -- local-save` exit 0** (2026-10-07, two consecutive runs, 0 blockers) — the document is read out of `localStorage` rather than off the live model, the runtime's own module re-encodes the live document to exactly the stored bytes (715 B in the recorded run), a reload restores the journalled place while the panel's `save v1 · local · places 1/128 · items 0 · writes 2 · 712 B` line agrees field for field with the model, a saved `showDebug` opens the review panel on mount and `F3` moves the panel and the document together through the one handler, a collected instance comes back as progress rather than a respawn, a v0 document is migrated **and written back as v1**, a future and a corrupt document are both refused with the runtime mounted and the bytes kept, 60 idle frames write nothing, a change inside the interval is coalesced (10 of 10 ticks) and a change past it writes once, and a 128-place document is trimmed oldest-first to fit a reduced ceiling. Seven negative controls each exit 1 (the toggle stops writing; the journal is never captured; the item layout ignores restored ids; the ladder keeps a stale id; the ladder stops repairing `0`/`1`; a future document is merged instead of refused; the interval is ignored). **One design correction is recorded rather than hidden:** removing the ladder's `dirty = true` after a migration does *not* fail the gate, because both runtimes rewrite the document on mount anyway — the flag is belt-and-braces for a read-only consumer, not the thing that upgrades the file in the product. **Recorded gap:** the research (§4.7) names IndexedDB; the shipped adapter is a synchronous three-method `localStorage` adapter, because both consumers need the settings applied *during* mount and the resume path runs before the first frame. The open step is an async IndexedDB adapter behind the same interface, not a defect in the gate.

- `ENV-04` — Added `src/engine/WeatherState.js`, the weather state machine both runtimes now run. Eight states — `clear`, `haze`, `overcast`, `rain`, `storm`, `dust`, `snow`, `mist` — each a row of **fifteen response fields** (`cloudCover`, `cloudDarkness`, `lightScale`, `hemisphereScale`, `exposureBias`, `fogDensity`, `fogTint`, `fogWarmth`, `fogLightness`, `wetness`, `ripple`, `cloudSpeed`, `birdActivity`, `beeActivity`, `particleIntensity`), so a new consequence is one table entry and one consumer rather than a new code path. The macro climate is derived from the latitude and the season (`tropical`, `monsoon`, `semi-arid`, `temperate`, `cold`), the seed is the coordinate hashed as `provider|lat|lon` at ~100 m resolution, and the clock is **the time-of-day clock**, so the sky and the sun cannot disagree about the hour. A climate's zero weight is a **prohibition**, not a rarity: snow cannot fall in the semi-arid band at any window of any year, and dust cannot blow in the cold one.
- `ENV-04` — The schedule is **random-accessible** and that is the whole determinism argument: a day is anchored once by a hash and walked at most fifteen Markov steps, so the state at window 900 is answered directly rather than by replaying 900 windows. A late joiner, a save/reload, a clock jump and a session that watched every frame therefore agree by construction, which is what `NET-01` will need and what the gate checks by re-navigating and comparing. Transitions happen **over time**: the response cross-fades linearly across the first eighteen minutes of each ninety-minute window, so the state is discrete and the sky is not — continuity is asserted in the clock (a five-minute step may not move a field by more than a fade step allows) rather than described.
- `ENV-04` — The first version of this module had the schedule's clock **wrap into a single day**, which made it a daily loop: at 23:55 the sky was the last window of the day and at 00:00 it was the *same* day's first window, a snap with no cross-fade — a per-boundary roll of the exact kind §9.2 forbids (*"transition over time rather than roll independently each frame"*). Found by the gate's continuity sweep, not by review. The clock is now unwrapped (`day × 1440 + minutes`), the day is an explicit input both runtimes take from `TimeOfDay.dayOfYear`, and midnight is a window boundary like any other: the last window of a day fades into the next day's anchor, measured as a worst field move of `0.0000` across the boundary.
- `ENV-04` — The first response wrote **absolute** fog and cloud colours, which would have made a dusty night brighter than the sky it was meant to obscure. Fog is now a multiplicative **tint** of the hour's own colour (`fogColor × blend(neutral, warm|cool, amount) × lightness`), and the cloud tone is applied *relative* in the dome shader (`cloudTone × mix(1.0, 0.34, uCloudDarkness)`), so weather can only ever darken or hue-shift what the clock produced. It is a gate clause now, not a convention: the browser tier requires a storm's fog to stay under the hour's colour times the largest warm tint, and a negative control that makes the tint absolute fails on both that clause and the `clear` identity.
- `ENV-04` — Applying a state writes **absolute composed values**, so the two integrations can run in either order and a repeated apply cannot compound. `clear` is the arithmetic **identity** of the pre-weather frame: every scale is 1, every additive term is 0, the fog range is the runtime's shipped 78/175, the fog colour is the hour's own colour to the last bit, the dome carries the hour's own cloud cover, and the water is unwet — asserted with `===` in Node and re-measured from the live scene and pixels in the browser. This is what let the shipped frame stay the frame the project already had.
- `ENV-04` — Two sky/uniform edits carry the response. `src/engine/ProceduralEngine.js` gains `uCloudDarkness` (the shader's cloud band multiplied by up to `0.34`) and `uSkyTime` (the cloud cells drift by `uSkyTime·(1.0, 0.6)`); `src/geo/GeoWorld.js` gains `uWeather` on the water shader, where `x` scales the normal and its drift and `y` tightens the fresnel, darkens the body and raises the alpha. Both are `0` at clear, and **no geometry is switched to show weather** — the coordinate world adds no draw call, the curated world's water takes the shared fallback (normal scale and roughness against the material's own base values), and the gate checks that the scene's child count is identical across all eight states.
- `ENV-04` — The habitat response rides the ambient scheduler's **existing** channel rather than a second animation path (`AGENTS.md` item 6): the phase decides the budget through `GEO_AMBIENT_ACTIVITY_BY_PHASE` and the weather decides how each species spends it through `world.setAmbientActivity(activity, speciesActivity)`. The gate measures both halves live: at one clock, clear draws **7** agents and a storm draws **2**, while `world.ambientActivity` is **1** in both — so what wound the ambience down was the species shares (`bird 1 → 0.10`, `bee 1 → 0.05`) and not a second clock.
- `ENV-04` — The uniform-write budget is `ENV-02`'s, kept for the same reasons: on change, and at most the profile's ceiling (`low 10 Hz`, `balanced 15`, `high 30`). A frozen clock writes **nothing** (0 writes over 60 frames in the browser, 0 over 60 in Node), a clock that jumps an hour spends **one** write rather than replaying the windows it skipped, and a synthetic 60 fps drive advances twelve world hours (720 world minutes, one per frame) in 33 writes with a busiest second of 4. The cloud-drift uniform is part of that budget rather than an exception to it: it advances only on a frame that earned a write, which is why the shipped configuration — a still clock — is a still sky.
- `ENV-04` — The **low profile is the fallback and the fallback is proven**: it runs zero particle families (`GDO_WEATHER_PROFILES.low.particleFamilies 0`, cap 0), so every state has to be legible without particles — the gate compares all **28** pairs on the uniform response alone and requires each to differ, and drives each of the eight states through the live runtime to read its dome, water, fog, sun, exposure and pixels back (storm 0.403 mean luma against clear's 0.493, fog 54/115 against 78/175, water 1.00/1.00 against 0/0). The research's particle ceilings (80 / 180 / 350) are kept beside the profiles as `GDO_WEATHER_PARTICLE_CEILINGS` for **`ENV-05`**, which is where camera-local precipitation belongs; this slice deliberately ships none.
- `ENV-04` — Wired into both runtime frame loops from the same clock. `src/geo/GeoGame.js` seeds from the coordinate and the provider, derives the climate from the latitude and `dayOfYear`, applies the weather *after* the time-of-day state, and exposes `weather`, `weatherState`, `weatherDiagnostics` and `refreshWeather()`; `setClockMinutes()` now moves both clocks, so a gate that sets an hour gets the weather that belongs to it. `src/reference/Environment.js` takes an optional `weather` state, applies it after the shared time-of-day state, tints the curated sky's background from a base re-captured by every time-of-day apply (so it cannot compound), reaches the water through the shared fallback, and reports `weatherDiagnostics`. `src/reference/main.jsx` builds the curated instance and now also passes `timeOfDay`, `weather` and the material library through its context-restore path — a restored runtime without its clocks would quietly have been a different world.
- `ENV-04` — The curated fixture's default sky is now a **seasonal** one, and that is deliberate: at 20.5°N in the monsoon band the schedule gives `overcast` at solar noon, where the coordinate fixture (28.98°N, semi-arid, seeded by its own coordinate) gives `clear`. The identity guarantee is therefore stated for the `clear` state rather than for "whatever ships": the coordinate frame is unchanged, and the curated frame is now the weather that its latitude and season imply — deterministically, and on the panel.

The scenario reads that line with a regex, so the panel and the gate cannot drift apart.
- `ENV-04` — Added the Node gate `src/engine/WeatherState.test.js` (11 tests, part of `npm run check`): random access equals the walk at window 900, `Math.random` is replaced with a thrower for the duration, a second session agrees, the schedule's own sequence is a function of the seed, the climate **and** the day, midnight is continuous, every climate's prohibitions hold over a year of windows of *every* state it allows (so no weight is decorative), the composition is bit-exact at `clear` and stays above the readability floor across a year × clock × state sweep (worst retention `0.5466` against a declared `0.52`), a starved state **fails** that floor so the bound has teeth, the low profile's pairs are all distinguishable, the apply path writes uniforms/lights/materials and nothing else, the write budget and the jump rule hold, and bad inputs are refused by name.
- `ENV-04` — Added the browser tier `npm run visual:audit -- weather-state` (exit 0, 2026-10-07). It drives **both** runtimes: the coordinate half re-navigates to prove cross-session determinism and compares the runtime's own schedule against the module's random-access sampler window by window, then measures the write budget, then the response matrix (eight states, one clock, a `clear` reference at the same hour), the fog-tint bound, the habitat response and the scene-growth check; the curated half drives the same two states through the same machine and reads back its background (0.293 → 0.184), water normal scale (0.550 → 0.880), roughness (0.420 → 0.360), fog (88/185 → 61/122), sun (3.20 → 1.66) and frame luma (0.648 → 0.548). - `DET-09` — Added `src/geo/GeoLandmarkGrammar.js`, the compiler the two shipped landmarks are now declared to, and `src/geo/GeoLandmarks.js`, their declarations. Before this, the Gateway and the Chariot were the only structures whose collision was written **twice**: `gateway()`/`chariot()` stamped boxes into the chunk's `VoxelBatch` and `createLandmarkCameraBlockers()` listed the same compound by hand as 34 `Box3`s, with nothing tying the two together. A landmark is now masses, repeats and accents; the repeat kinds are `grid`, `walk`, `arc`, `ring`, `stack` and `line`, a `grid` may nest (four wheels of sixteen rim stones is `grid × each{arc}`), and the compiler admits one outer **site** at a time against a box budget or none of it. `GEO_LANDMARK_BOX_BUDGETS` is `low 120 / balanced 220 / high 400`; overflow drops accents first, then surface, never silhouette, and every drop is counted (`budgetSkips`). Both shipped landmarks fit the low budget with room (50 and 108) and drop nothing.
- `DET-09` — Openings are declared as **profiles** rather than as a gap: a void is a bottom, a depth and a stack of bands (`top`, `halfWidth`), because a real arch steps inward as it climbs — the Gateway's passage is 4.5 m half-width to 13.35, then 3.6, 2.95 and 2.3. `boxIntrudesIntoVoid` tests a box's y-range band by band, which is what lets the lintel sit legally above the head while a box sharing a band's height must keep clear of that band's width. Two rules the compiler enforces instead of documenting: an **accent** that declares collision is rejected at definition time, so §17.2's *visual boxes that create colliders automatically: 0* is a rule rather than a review habit; and the tolerance (`GEO_LANDMARK_VOID_TOLERANCE = 1e-4`) applies **vertically as well as horizontally**, because the voussoirs are *defined* by the band edges — a stone whose lower face *is* a boundary overlaps it by 1e-15 in binary floating point, and an exact comparison silently dropped two stones of the shipped arch the first time the profile was entered.
- `DET-09` — The port is **geometry-neutral**, and that is measured rather than asserted. `src/geo/GeoLandmarks.legacy.js` is a parity table captured by **executing** the pre-port `gateway()`/`chariot()` loops against a recording stub, not by transcribing them; the Node gate recompiles the declarations and requires all **158** boxes to match — position, size, **rotation and colour** — so the port cannot quietly move a wall while a screenshot improves. The ids the shipped gate addresses are preserved too: the module templates are `pier:{side}` and `tower:{x}:{z}` (not `piers:`/`towers:`, which silently produced `gateway:piers:`), and the chariot's historical numbering is reproduced through a `{ndz}` placeholder plus a per-module `proxyIdScale`, because its ids index the *descriptor* offset (±5) while the drawn geometry sits at ±6.5 and ±3.5 with two different multipliers. Re-running `curated-camera` confirms it: exit 0, 0 penetrations across all twelve sweeps, `gateway-pier-compressed` frame unchanged.
- `DET-09` — Two real errors in the port were found by the gate rather than by review. First, the free half-width of an opening **did not end at the arch head**: `landmarkVoidHalfWidthAt` returned the last band's width above the last band's top, so a probe above the arch could report a passable gap between two voussoirs and the function's own docstring (*"or 0 outside its profile"*) was already describing the fix — it now returns 0 there, which is what makes the lintel legal and the head impassable. Second, the wheel collider still **cut the drawn rim**: sixteen stones sit at radius 3.0 and are rotated to face the hub, so the ones at 45° reach a *corner* 0.7 m further out — a circumscribed radius of **3.7 m** — and the port's first declaration of 7.3 m, derived from the tangential half-width, was 5 cm short. The declaration is now 7.4 m and the test measures the reach as the box's **support along the outward direction** rather than half of whichever side happens to be longest. The pre-`DET-09` 7.0 m slab cut 0.2 m off the rim; that is a deliberate change rather than parity, and it is recorded as one.
- `DET-09` — `src/reference/BiomeManager.js` now **stamps** the compiled landmarks into the chunk batch it already builds and **derives** its camera blockers from the same compiled artifact, so the geometry and the collider cannot drift: `createLandmarkCameraBlockers()` is 34 boxes with the pre-port ids, and a new `landmarkDrawPlan()` reports the draw cost per landmark (one material family each — one instanced draw each — against the low budget). Both shipped landmarks are single-material, which is why the 108-box Chariot costs no extra draw call; the six roof tiers that used to be two interleaved loops are one loop with a `colorCycle`, which keeps them one family *and* keeps six distinct proxy ids, after the first port attempt ran them as two single-colour modules sharing one id template and produced duplicate `chariot:roof:0..2` ids.

- `ENV-02` — Added `src/engine/TimeOfDay.js`, the single solar state both runtimes render from. One model produces solar declination and hour angle from the clock, the latitude/longitude and the day of year, and the **phase is a band of solar elevation** rather than a separate schedule, so a phase that contradicts the sun is not a state the system can reach — the Node gate checks every minute of a full day rather than four samples. Phases: `night`, `blue-hour`, `sunset`, `low-sun`, `golden`, `day`. `sunrise` was renamed `low-sun` on purpose: the same low elevation happens at dawn and dusk, and a phase name that asserted a time of day would be wrong half the time it was used. The default clock is **solar noon at the world's own longitude** (06:49 UTC at 77.7°E, elevation 84.5°) rather than a fixed UTC hour, because a runtime that starts at local noon everywhere is the only default that does not need per-coordinate tuning.
- `ENV-02` — The uniform-write budget is a property of the binding rather than a budget someone has to police. `bindTimeOfDayUniforms(sky, state)` points the sky's uniforms **at the state's own `THREE.Color`/`Vector3` instances**, so applying a state is `markApplied()` and nothing is copied. `update(delta, nowMs)` returns whether a write is *earned*: a per-profile ceiling (low `10 Hz`, balanced `15`, high `30`) plus "on change" with an epsilon on the phase, the elevation (0.05°), every colour, the exposure and the star term, and a stall coalescer so a background tab does not earn a burst of writes when it resumes. `rebaseClock(nowMs)` exists because a driver with its own timeline (a capture, a fast-forward, the gate itself) otherwise travels backwards past the last write and is refused every one — which is exactly what the first run of the browser gate measured, zero writes in 180 frames.
- `ENV-02` — Night is readable by construction rather than by tuning: `GDO_NIGHT_LUMINANCE_FLOOR` is checked across the whole cycle, the sky dome gets stars from a hashed direction field and a moon disc **in the same fragment pass**, so night costs no extra draw call and no texture, and the ambient budget is driven from the same state (`GEO_AMBIENT_ACTIVITY_BY_PHASE`) through `world.setAmbientActivity()` — `AGENTS.md` item 6's rule that a dusk state winds a family down without a second animation path. Birds and insects roost at night (`night` → 0.35) rather than being switched off.
- `ENV-02` — Wired both runtimes from one state. `GeoGame` builds the sky with `sky: false` and applies the state only when `update()` says so; the curated runtime's `Environment` takes `timeOfDay`, applies the same state to its light rig and **regenerates the PMREM environment map once per phase** (`environmentPhases`, `environmentMapBuilds`), so "bounded work" holds on the runtime that has an IBL pipeline too. The debug overlay gained a `time … UTC · phase … · sun … · light … · stars … · exposure … · writes … / ceil …Hz` line, which is the surface a reviewer reads.
- `ENV-02` — Added the Node gate, `src/engine/TimeOfDay.test.js` (8 tests). It found **three real module defects** rather than confirming the design: `solarPosition()` returned a shared scratch object, so a caller that kept the result was silently handed the next call's answer; the per-frame `sample()` built a `mix` closure that allocated ~86 B per frame; and `setClock()` did not re-sample, so assertions read stale colours until a sample was taken. - `ENV-02` — Added the browser tier, `npm run visual:audit -- time-of-day` (exit 0, 2026-10-07), and it is the tier that found the fourth defect: the review panel threw `Cannot read properties of undefined (reading 'toFixed')` because `diagnostics()` did not carry `exposure`, which had been invisible for as long as no one had executed the scenario. - `GME-06` — Added `src/engine/DiscoveryJournal.js`. A place's id is a pure function of its name, kind and a **100-unit cell** — not of insertion order, tile iteration or the order the player walked past it — so the same street yields the same id in a second session, after a tile rebuild, and in a save file that `NET-01` has not written yet. The cell size is 100 rather than a small quantum on purpose: quantisation flips at every bucket edge, so the first version's 0.5-unit quantum changed an id under a 0.2-unit anchor shift and a rebuilt tile would have logged a second discovery. Names are case- and whitespace-folded, because map providers disagree about both for the same street.
- `GME-06` — The state is bounded in bytes and in capacity. The storage is preallocated (fixed arrays plus `Map` indices), so a player who crosses the whole map holds what a player who crosses two tiles holds; `update(position, candidates, { now })` returns only what **entered** the journal, and a candidate the full journal cannot retain is *declined* rather than announced, so a resident label set re-offered every frame cannot spam a HUD with the same discovery. The accounting identity `discovered - evicted === size` holds after every offer and is asserted in both tiers.
- `GME-06` — Found and fixed two design defects while writing the gate: eviction returned its slot to the free list **without taking it back out**, so the journal grew past its own capacity (measured: size 5 at capacity 4); and unconditional displacement made the retained set a function of walk order (measured: `tie-3` surviving one direction, `tie-0` the other). The second is fixed by the decline rule, not by the id tie-break direction — the browser gate's first written control for it *passed*, which is how the record knows which of the two rules the property depends on.
- `GME-06` — Fed the journal from the **resident** labels rather than from the ones the HUD is showing, and that is a defect the regression sweep found rather than a design choice made in advance: the first wiring read `displayedLabels`, the label layer displays at most 14 names chosen by *static map priority*, and a browser run that passed twice in isolation then failed inside the full sweep with *"a reloaded session did not record the same place"*. A place could therefore be undiscoverable whenever fourteen higher-priority names were on screen. `GeoGame` now gathers what `GEO_DISCOVERY_MAX_RADIUS` reaches over the resident tiles (a reused array, one distance test per resident label, four times a second) and the journal applies its per-kind radius to that set, which is what the research actually says — *enter a radius to unlock the place*. Discovery is a radius test, not a HUD test.
