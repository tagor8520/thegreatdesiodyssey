# Feature Changelog

All significant feature, architecture, research, budget, and roadmap changes are recorded here. Entries use local project dates (`Asia/Kolkata`) and canonical IDs from [`README.md`](./README.md).

This project does not yet publish semantic releases. Until it does, changes are grouped by date and implementation state. A source change is listed as **Added** only after its test/build gate passes; unfinished work stays under **In progress**.

## Unreleased

### In progress

- `MAT-03` — The low-pixel-ratio shimmer capture that was the recorded blocker has now been **run**, at the production adaptive pixel-ratio floor of `0.6`, and it is **inconclusive**. Measured against a mip-disabled control and against a positive control with the *entire* anti-alias policy stripped, the 99.9th-percentile frame-to-frame luma delta stays pinned at `4.1` in every configuration (`1.000x` sensitivity): the statistic cannot detect aliasing even when the policy is removed, so it certifies nothing. The task stays `PARTIAL`; the open gate is now a real-GPU capture. **An earlier `0.890x` figure reported here has been withdrawn** — see Changed.

### Added

- `GME-05` — Added `src/engine/ActionRegistry.js`, the single gameplay action surface for both live runtimes. Twelve actions (`forward`, `back`, `left`, `right`, `run`, `jump`, `camera`, `map`, `debug`, `selectSlot1-3`) are declared with their `kind` (`hold` = active while down, `tap` = fires once and ignores auto-repeat), keyboard `codes`, `runtimes`, `surfaces`, touch control (`button` with `text`/`grid`/`size`, or `joystick`), `group` and inventory `slot`. `assertActionRegistry` throws naming the problem, and the invariants it enforces are the silent ones: a code bound to two actions in one runtime (the loser simply never fires), a `ui` or `touch` surface claimed without a control, two touch buttons in one grid cell, two inventory actions sharing a slot, and a button smaller than the 44px touch-target floor.
- `GME-05` — Added `ActionInput`, the only object in either runtime that registers `keydown`/`keyup`/`blur`. It owns the held set, the virtual set and the analogue vector, resolves codes **per runtime** (`KeyM` is map mode in curated and nothing in coordinates), looks the code up before the veto so `unknownCodes` counts keys this mode does not bind while `ignored` counts its own presses arriving while the runtime is not accepting input, and clears everything on blur while telling the owner. `dispose()` removes exactly the three listeners it added — the property `FND-07` measures.
- `GME-05` — Added `src/engine/TouchControls.js` (moved from `src/geo/GeoControls.js`, which remains a re-export shim) and `src/engine/touch-controls.css`: the touch layer is now **generated from the registry** by `mountTouchControls`, with the joystick zone declaring which analogue actions it speaks for. Moving the rules out of `src/geo/geo.css` fixed a real mobile defect the previous CSS carried: buttons took their height from their text and aligned to the end of their grid cell, so RUN and MAP rendered **15px tall** on a 390px phone. Sizes now come from `touch.size` in the registry with a `min-width/min-height` floor beneath them.
- `GME-05` — Added the Node gate, `src/engine/ActionRegistry.test.js` (14 tests, part of `npm run check`). Beyond the registry invariants and the input behaviour it carries two checks no runtime assertion can make: the rendered markup's button and joystick sets are compared against the declarations per runtime, and **the whole `src/` tree is scanned to prove no module outside the registry names a registered gameplay key**. That scan is what the gate's own title means — a second `['Digit1','Digit2','Digit3']` array or a second `F3` listener is how "one named surface" decays, and no test can enumerate call sites that do not exist yet. The frozen `/classic.html` explorer is excluded by an explicit written list, per the `AGENTS.md` rule that no new work goes into `src/world/`, `src/ui/` or the legacy `src/engine/` controllers.
- `GME-05` — Added the browser tier, `npm run visual:audit -- action-surfaces` (exit 0, 2026-10-05). It drives both shipped runtimes through the real landing flow and presses the mounted controls with real events: pointer events on the buttons, a pointer drag on the joystick (`z=-1.000` → `forward`, released to `x=0 z=0`), and `KeyboardEvent`s on the page's own listeners — never a call into `setVirtualInput`, because that would test the layer under suspicion. It also asserts the two modes' bindings are disjoint, reaches every inventory slot by both its button **and** its key, and finally reloads both runtimes at 390x844 with touch emulation, where the runtimes must decide for themselves to show the controls (curated run 52x52, jump 72x72, map 46x46; coordinates identical with `camera`) while a mouse-driven browser still gets `data-mobile="false"`.

- `FND-08` — Added `src/engine/WorldDomain.js`, the named curated/coordinate domain interface: six members (`supportAt`, `collidesCircle`, `moveCircle`, `resolveGroundStep`, `clipCamera`, `readDiagnostics`), a declared arity floor for each, and a frozen `scale` descriptor whose fields carry the same meaning in both modes. The interface is **declared, not inferred** — the coordinate runtime answers these questions from `GeoWorld`, the curated runtime from `CuratedDomain`, and until now the only thing that said so was convention. `assertWorldDomain` names every missing or malformed member in one message; `describeWorldDomain` reports completeness; `compareDomainScales` and `probeWorldDomain` are the gate's two halves.
- `FND-08` — Added `src/reference/CuratedDomain.js`, which adapts the curated runtime's scattered traversal surface into that interface: `BiomeManager`'s 4 m terrain lattice, the bridge manager's rail boxes and deck heights, and the player's private collision box. It is an adapter, not a rewrite — the `.6` rail half extent, the centre-based world bound, the axis-separated revert, the highest-surface rule (`max(terrain, deck)`, including `heightAt`'s `-Infinity` on open ground) and the `.55` step ceiling are all the shipped rules moved behind a name. Curated deliberately reports `walkable: true` at every sample and no slope, because its 4 m lattice exposes no normal and traversal is decided entirely by the step policy; that difference is documented in the module rather than hidden by the interface.
- `FND-08` — Added the shared `supportUnderFoot` sampler. Both players already took the highest support over the four corners of a square footprint; the helper names it and takes the footprint half extent from the caller, so the magic `.55` exists once instead of in two runtimes. The winning corner's whole support record travels into `out`, not just its height, and both scratch objects are module-level so a grounded frame allocates nothing.
- `FND-08` — Added `src/engine/WorldDomainProbe.js`, the lane construction and probe orchestration both tiers import, so the Node test and the browser scenario cannot disagree about what "the interface holds" means. Every lane is **found, never hard-coded**: it searches for a start that is clear of static geometry *and* whose reverse camera control is unblocked, then proves the forward segment is blocked. Two attempts at choosing a lane by eye during this work produced a lane already inside a building and a curated start with a bridge pier behind its control segment.
- `FND-08` — Added the Node gate, `src/reference/WorldDomain.test.js` (7 tests, no browser). It drives a real `GeoWorld` with a compiled fixture *and* a real `BridgeManager` through one identical probe, and judges both with the same function. It carries five negative controls, because a check that cannot fail proves nothing: a domain with a missing member, a domain with a 2-parameter `collidesCircle`, a domain that never reports a contact (which must fail its own judgement), a domain that adopted coordinate's camera clamp, and a domain whose footprint drifted off the 1:10 ratio.
- `FND-08` — Added the browser tier, `npm run visual:audit -- domain-interface`, which loads the same probe module into the page and runs it against the shipped runtimes through the real landing flow, then judges the returned records in Node with the same `judgeWorldDomain` the Node tier uses. Exit 0, 2026-10-05 (see `VISUAL_GATES.md` §4 A4d for the full table).
- `FND-08` — Added `src/engine/FlatDomain.js`, a forty-line in-memory domain used by tests, and moved the first of the two tests that had hand-rolled fake worlds onto it; the second keeps its own specialised double (a sloped support so a rejected transition can be exercised) and gained the `readDiagnostics` member the interface requires. Those fake worlds were the reason `GeoPlayer` carried a compatibility path for "lightweight test/embedding worlds"; making the interface required exposed that the fallback had never been exercised against a real world, and that no test would have noticed had it been wrong.

- `COL-09` — Added `src/geo/GeoDynamicProxies.js`, the capped dynamic spatial hash that carries moving solids beside the static per-tile grids. It admits exactly four primitives — circle, capsule, AABB, oriented box — each validated with an explicit finite Y span, plus compounds capped at four primitives; a mesh, a rendered object, a nested compound, or any malformed number is rejected by name rather than coerced. The cap is enforced by rejection: `GeoDynamicProxyCapError` names the profile, the cap, the owner that did not fit, and why eviction is not an option, and a rejected insert leaves the population and the query result untouched.
- `COL-09` — Added the storage and re-bucketing contract. Every typed array is sized to the profile cap in the constructor, so `add`, `update`, `collect` and the exact tests allocate nothing at steady state, and a test asserts `bytes` is unchanged after filling all 64 low-profile slots as well as that the candidate buffer is one reused allocation across 500 queries. Each slot caches the integer cell range it is bucketed into, so a proxy sliding within its cell costs one bounds recomputation and no re-bucketing; `diagnostics.reinserts` counts exactly the boundary crossings, and the test drives a slide that produces zero, then one, then three. A 12-unit box spanning 16 buckets is a single candidate per query via a stamp array, not sixteen.
- `COL-09` — Added exact sweeps for every primitive by reusing the static path's exported math instead of writing a second solver: `sweepPointAgainstSegmentCapsule` (now exported from `GeoCollision.js`) with the moving radius folded in gives an analytically exact test for circle and capsule targets, and the box path is the shared `sweepPointAgainstAabb`. An oriented box is the same AABB test performed in the box's rotated local frame with the contact normal rotated back. Capsule-side, capsule-cap, corner, boundary-touching and rotated-face contacts are each asserted at their computed time.
- `COL-09` — Merged dynamic solids into the live queries. `collidesCircle`, `sweepCircle` and `sweepSphere` now query both structures and report the earliest contact; a dynamic contact is tagged with `dynamicHandle`/`dynamicOwner` and clears `tileKey`/`polygonIndex` so a caller can tell it from a tile footprint. Mask and Y-span filtering apply identically to both, so a `SOLID|CAMERA` vehicle stays out of `PLACEMENT` queries exactly as a building does. `GeoWorld` owns the hash (`addDynamicProxy`, `addDynamicCompound`, `updateDynamicProxy`, `removeDynamicProxy`, `removeDynamicProxiesFor`, `dynamicProxyDiagnostics`), disposes it with the world, and takes the profile from `GeoGame` (`dynamicProxyProfile`, default `low`).
- `COL-09` — Added the 64 ceiling to `GDO_LOW_PROFILE_BUDGETS.dynamicProxies` so the low-profile budget reports an over-cap world, and surfaced the active count through `collectGeoFixtureBudgetMetrics` and the debug overlay's query line.
- `COL-09` — Added `tools/visual-audit/diagnose-dynamic-proxies.mjs`, the live proof, run against `dense-urban` with mapped buildings resident (exit 0, 2026-10-05). It reports the live profile (`low`), cap (`64`), the preallocated storage (`8320` bytes), and the profile/cap agreement with the budget ceiling; proves a placed solid changes a **verified-clear** lane from no-hit to hit at `t=0.4188` for both `sweepCircle` and `sweepSphere`; refuses the 65th insert with the message naming profile and owner while the existing proxy stays solid; shows storage-slot reuse with a fresh handle (`handle 1, slot 0` released → `handle 2, slot 0`); and shows the static world byte-identical across add and remove (`1 tile, 360 collider floats, 3571 bytes` before and after, `0` proxies left behind).

- `FND-07` — Closed the shared lifecycle/disposal contract with a gate that measures repeat remounts instead of a single clean teardown. `src/engine/ResourceLedger.js` installs counting instruments for the five classes the gate names — workers, observers, listeners, geometries, textures — and `src/engine/ResourceLedger.test.js` drives three construct/dispose cycles, asserting that a remount terminates exactly one worker and creates exactly one, that the worker's `message` and `error` subscriptions are removed rather than left on the terminated instance, that every armed geometry and texture fires `dispose` (ownership, not object count: `renderer.info.memory` is per-renderer and a remount replaces the renderer, so counting cannot see across the boundary), and that net live listeners return to baseline. `src/geo/GeoTestSupport.js` now holds the single implementation of the fixture-mount sequence so the lifecycle proof and the byte-equivalence proofs drive a world identically.
- `FND-07` — Added the browser tier, `npm run visual:audit -- remount-lifecycle`, which measures all five classes through the real landing flow in both the curated runtime and Coordinate Explorer. A warm-up cycle absorbs one-time page initialisation — `react-dom` registers a delegated `selectionchange` on `document` the first time it needs that event type, and Vite injects a `<style>` into `<head>` on the first lazy CSS import — and every measured cycle must then return **exactly** to the warm reference, so one-time initialisation can never be used to hide steady accumulation. Measured 2026-10-04, exit 0: coordinates `1 worker / 2 observers / 41 live listeners → 0 / 0 / 6` with `11/11`, `11/11` and `26/26` geometries released and **zero orphaned subscriptions**; curated `0 / 1 / 167 → 0 / 0 / 7` with `83/83`, `89/89` and `75/75` released and `0` outstanding. Scene content is reported but not asserted: both runtimes stream, so the mounted geometry count legitimately varies between mounts, and the lifecycle property is that nothing survives.
- `FND-07` — Added `tools/visual-audit/lifecycle.mjs`, the shared instrument, and its collectability step. Counting subscriptions cannot by itself distinguish an app leak from a detached target that the instrument is still holding, so the probe drops its own references to orphaned targets, forces a collection over CDP, and reports how many the page still holds. That measurement is what separated a real finding from a false one — see §6.F3 — and it is the reason orphaned counts are reported rather than asserted.

The scenario needs the dev-only audit bridge, so it cannot run against a built bundle; the probe drives the same real landing UI with instrumentation only, then performs the same warm-reference and collectability checks. - `MAP-08` — Proved the normalized provider feature schema end to end and closed the gate. A new test compiles the canonical `provider-equivalence` fixture through the production builders under both provider vocabularies and asserts every provider-invariant output is byte-identical: road positions and indices, building footprints, exact footprint colliders, water polygons, land cover, water-domain vertices, and semantic water classes. It guards against vacuous success by first asserting the fixture actually produces roads, buildings, water and colliders, so empty-vs-empty cannot pass, and it asserts the divergent half too, so equalizing the providers by accident fails rather than silently passing.

The encoder is development tooling and is imported by no runtime entry point.

- `COL-05` — Closed the coordinate TPP camera sweep gate. `npm run visual:audit -- coordinate-matrix` sampled **480 frames** across five fixtures (`dense-urban`, `concave-building`, `courtyard-hole`, `sparse-rural`, `stacked-bridge`) at both wheel-clamp extremes (`1.2` and `8`) with **0 penetrations** and 0 gate-relevant console errors. The world's own `exactTests` counter advanced by **675**, proving the concave/courtyard exact-ring path ran rather than only the broad-phase AABB proxy.
- `COL-05` — Closed research item §15.3-3 by measurement rather than assumption. The probe scans yaws at maximum distance to find a genuinely obstructed pose, then jumps from a clear pose straight into it — the worst case, with no gradual approach to hide latency. - `LAY-03` — Closed the transparent-water gate on all four recorded criteria. Order stability: the probe renders the identical scene twice back to back inside one task with no clock advance, so identical inputs must give identical pixels — **24/24 renders were pixel-identical** across 4 cardinal directions x 3 grazing pitches (`.02`, `.05`, `.1`) x 2 distances, `maxDelta = 0`. Band ordering: `water@100` against a highest opaque band of `1`, so water always blends after opaque geometry has written depth; opaque layers legitimately share band `0` because they depth-write. Duplicate blending: `provider-equivalence` resolves `water` (OpenMapTiles) and `water_polygons` (Shortbread) to identical geometry — 1 mesh, 2 triangles, 1 water domain, 4 classes — drawn once. Blended foliage: exactly **one** transparent material exists in the scene (the water `ShaderMaterial`, `depthWrite: false`); non-water transparent materials are **0**.
- `QLT-06` — Fixed two measurement defects that had made the shimmer scenario's numbers meaningless and its runtime unusable. (1) Raw pixel frames were being returned to Node — roughly 12 MB per measurement across the CDP bridge — which dominated runtime; runs took ~16 minutes and one exceeded a 900 s protocol timeout with no verdict. The statistics are now computed inside the page and only numbers cross the bridge, so a full run takes ~14 seconds. (2) The water shader's `uTime` animation phase was left running, so successive measurements sampled different wave phases; it is now pinned (`frozenWavePhase`) so every configuration is directly comparable. Added a positive control that strips the whole anti-alias policy, and replaced the mean with p99.9 and hot-pixel statistics, because a mean over a mostly-flat crop averages localised shimmer away to nothing.
- `QLT-06` — Extended the visual-audit harness with three coordinate scenarios (`coordinate-camera`, `coordinate-matrix`, `water-order`) plus `shimmer-low-dpr`, and with fixture selection (`--fixture`, `--variant`) so any canonical fixture can be driven from the command line. Added a device-scale-factor parameter for the low-pixel-ratio condition and a `KNOWN_CONSOLE_DEFECTS` classifier: tracked-known errors are still printed and written into every `report.json`, and only gate-relevant ones fail the run — nothing is filtered silently.
- `QLT-06` — Recorded the `gdoPlantClearance` vertex-attribute defect discovered while running the coordinate audits (`VISUAL_GATES.md` §6.F1). The plant pool geometry occupies exactly the 16 attribute slots the WebGL floor guarantees, and SwiftShader's linker rejects a program sitting exactly on that boundary, so the plant material never links in the affected profiles. It is **pre-existing and unrelated** to this work — reproduced identically with the entire wind change stashed — and is left unfixed because reclaiming a slot touches the vegetation slice and needs its own feature-slice change.

## Changelog rules

For every future change:

1. Add the canonical feature ID.
2. Use **In progress** until checks and required acceptance gates pass.
3. Record user-visible behavior, architecture/contracts, budget impact, fallback, and migrations—not every internal line edit.
4. Move a matrix item to **ADDED** or **PARTIAL** in the same change.
5. Record breaking seed/schema/save changes with old/new version and migration behavior.
6. Record rejected experiments when their measured result should prevent repetition.
7. Keep newest entries first; never rewrite old outcomes to imply unfinished work was complete.
