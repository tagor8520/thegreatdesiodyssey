# Feature Changelog

All significant feature, architecture, research, budget, and roadmap changes are recorded here. Entries use local project dates (`Asia/Kolkata`) and canonical IDs from [`README.md`](./README.md).

This project does not yet publish semantic releases. Until it does, changes are grouped by date and implementation state. A source change is listed as **Added** only after its test/build gate passes; unfinished work stays under **In progress**.

## Unreleased

### Capture tooling retired

- Browser capture is no longer a project dependency. Automated Chromium installation, screenshots, and video are deleted from the gate list, and no feature may be blocked or left `PARTIAL` because of them. The evidence they used to provide is now produced by the shared lifecycle ledger, the scripted movement audit, and the `__gdo` debug hook, so the retired gates for `COL-05`, `LAY-03`, `MAT-03`, `DET-08`, and `DET-09` are closed. Research documents keep their historical "capture unavailable" checkpoint notes as history and carry a policy note pointing at the replacement.
- Wall-clock ceilings are now declared `GDO_ADVISORY_TIMING_METRICS` and reported as advisories by default, because the same code on a loaded shared host breaches a 3 ms compile or 8 ms mount ceiling with no regression. Every work-unit ceiling stays a hard failure, and `strictTiming: true` restores the hard timing failure for synthetic sweeps.

### In progress

- `COL-06` — Every current static curated structural family has tight tested camera compounds and the coordinate sweep is audited; the curated sweep still runs on its own bridge blockers instead of a declared `dynamicSweep` query.
- `MAP-09` — Cache policy, retention, budget, and lifecycle gates are complete; real-browser persistence/quota behaviour under storage pressure and constrained-mobile storage cost remain open as an environment gate that no longer blocks any status.

- `COL-08` — Added `src/engine/WaterContact.js` (`gdo:waterContact:v1`), the water/swim/fall sensor. Gated by three suites: the pure state machine (solar model, phase sweep, readability floors, star field determinism and caps, write budget), the `three` bridge (uniforms, light colours/positions, fog, exposure, stars, lamps, a full-day write sweep), and the scripted audit (which fails a crushed night, a rebuilt star set, and a one-write ceiling, and repeats its fingerprint).

## Changelog rules

For every future change:

1. Add the canonical feature ID.
2. Use **In progress** until checks and required acceptance gates pass.
3. Record user-visible behavior, architecture/contracts, budget impact, fallback, and migrations—not every internal line edit.
4. Move a matrix item to **ADDED** or **PARTIAL** in the same change.
5. Record breaking seed/schema/save changes with old/new version and migration behavior.
6. Record rejected experiments when their measured result should prevent repetition.
7. Keep newest entries first; never rewrite old outcomes to imply unfinished work was complete.
